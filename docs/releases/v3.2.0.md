## 1. 升级前必读

V3.2.0 是**协议与校验增强版本**，保持 V3.1.0 的角色序列、五个 Gate、Evidence 模型与
`state.yaml` schema 版本不变。升级后行为变化集中在这三处：

1. **路线成为机器事实**：`state.yaml` 新增可选字段 `route`。新任务必须写入
   `NORMAL` / `COMPLEX` / `ARCHITECT`，并与 `task.md` 的 `## Complexity` 一致；
   五个 Gate 与 `workflow-check route` 都会拒绝不一致或非法取值。
2. **交接成为统一输出契约**：七个角色结束本轮时必须输出
   `RESULT / CURRENT_ROLE / NEXT_ROLE / NEXT_ACTION / NEXT_TARGET / HANDOFF_PROMPT`；
   跨角色失败必须附可直接执行的完整 Prompt。
3. **Git 出站有明确完成条件**：新增只读自检工具
   `.agent/specs/tools/git-lifecycle-check`，把 preflight / commit / push /
   remote verify / handoff 的时机变成可复核事实。

历史 Task 没有 `route` 字段时仍然可读、可通过既有 Gate；但 `workflow-check route`
默认 strict，历史任务需要显式 `--allow-legacy`。

## 2. 从 V3.1.0 升级的主要变化

| 领域 | V3.1.0 | V3.2.0 |
| --- | --- | --- |
| 路线决策 | `ARCHITECT` 依赖 Owner 指定 | **TaskBuilder 三选一路线决策**（Owner 指定仍是硬约束） |
| 路线事实 | 只存在于 `task.md` 散文 | `state.yaml.route` 为唯一机器权威源，五个 Gate 统一校验 R-1 ~ R-4 |
| 交接输出 | 各角色写法不一 | **七角色统一出站契约** + 失败十项 Prompt 模板 |
| Git 时机 | 分散在各角色 Prompt | **`WorkflowGitLifecycle.md`** 统一 Stage / Commit / Push / Gate / HANDOFF 条件与例外矩阵 |
| Git 自检 | 无 | 只读 `git-lifecycle-check`（preflight / commit-check / push-check / verify-remote / handoff-check） |
| 规范加载 | TaskBuilder 必读清单缺项 | Directive §4 为唯一权威清单，包含路线、熔断、Handoff、Git Lifecycle |
| 发布资产 | 5 个 Specs 的固定计数 | 显式 `REQUIRED_SPECS` / `REQUIRED_ROLES` / 工具可执行位校验 |

## 3. 路线选择（TaskBuilder）

- TaskBuilder 依据任务的**实际目标、范围和交付物**判定 `NORMAL` / `COMPLEX` / `ARCHITECT`，
  而不是任务名称、文件数量或实现工作量；
- Owner 明确指定的路线、范围与技术限制是硬约束；Owner 未指定时 TaskBuilder 必须独立判定，
  包括独立识别 `ARCHITECT`；
- 路线必须同时写入 `state.yaml.route` 与 `task.md` 的 `## Complexity`，两者不一致即
  fail-closed；
- 改变路线只能由 Owner 要求，且旧 Contract / Review / Owner / Delivery 证据全部失效，
  必须重新形成 A1 / A2。

Engine 只校验「已记录的路线事实」与可读证据是否自洽。它**不能**判断自然语言需求本身
应该属于哪条路线，也不能认证 Session 身份或 Git 作者。

## 4. 统一出站交接

- 标准块固定为角色最终回答的最后一个章节 `## 出站交接`，字段顺序固定；
- `NEXT_ROLE` 必须唯一；`NEXT_ROLE=NONE` 是合法停止；
- 等待 Owner 决策使用 `NEXT_ROLE=OWNER` + `NEXT_ACTION=OWNER_DECISION`，`HANDOFF_PROMPT=NONE`；
- DANGER 与合法停止必须 `NEXT_ROLE=NONE` 且不生成下游执行 Prompt；
- OwnerGate V1 → V2 是**同 Session 推进**，不是跨 Session Handoff；
- 跨角色失败必须提供十项完整 Prompt（接收 Role、仓库/分支/任务路径、Commit 与证据状态、
  路线、失败原因、应做什么、可改范围、应验证的 Gate、不得修改的内容、完成后下一步）。

这些是 Prompt 层契约。静态测试只能证明模板与出口表覆盖，不能证明某个模型在真实运行时一定服从。

## 5. Git Lifecycle 与自检工具

`WorkflowGitLifecycle.md` 固定六类 Commit（`BOOTSTRAP` / `EVIDENCE` / `METADATA` /
`ROLE_ARTIFACT` / `FORCED_EVIDENCE` / `REGISTRY_ONLY`），并明确：

- A1/C1/D1 中间 Evidence Commit 允许早于角色整体交接，但必须满足阶段边界、验证已执行、
  失败未隐藏、范围精确、工作区可解释、不宣称完成、后续 Metadata 可解析；
- `STAGE_DELIVERABLE_VERIFIED` 不是 `SESSION_COMPLETE`，中间 Evidence 不得被表述为 HANDOFF；
- DANGER write-ahead、Registry-only 与失败证据保存保留其安全语义；
- Push 失败、远端 SHA 不一致、Gate `FAIL`、工作区 dirty 时不得输出 HANDOFF；
- 远端核验使用真实 `git ls-remote`，不信任可能陈旧的本地 tracking ref。

`git-lifecycle-check` 是**只读**工具：它不 stage、不 commit、不 push，也不能阻止绕过它的
直接 Git 写操作。工具 `PASS` 不替代 Gate，`FAIL` 时不得继续写 Git。

## 6. 安装与发布

- 版本号：`.agent/VERSION` = `3.2.0`；发布 Tag 目标为 `v3.2.0`；
- 四平台 Binary（`linux/amd64`、`linux/arm64`、`darwin/arm64`、`windows/amd64`）、
  Source Distribution、`SHA256SUMS`、`version.json` 与 Release Notes 的 9 项附件契约不变；
- Source Distribution 现在必须包含 `WorkflowRouteSelection.md`、`WorkflowHandoffContract.md`、
  `WorkflowGitLifecycle.md` 与可执行的 `.agent/specs/tools/git-lifecycle-check`；
- 新增规范与工具按既有分类进入 `managed`，随升级安装到宿主并参与 B/L/N 比较；
- 升级不会改写历史 Evidence，也不会让旧 `CLEAN` / Owner Acceptance 自动复活。

## 7. 已知边界

- Engine 不拦截直接 `git commit` / `git push`；Git 出站约束主要是协议约束（SPEC_ONLY）；
- Engine 不能认证 Session 身份、Agent 作者或 Owner 指令的真实性；
- `handoffReady` 仍只比较本地 remote-tracking ref；Gate 自身可能在远端被推进时误 PASS，
  因此必须额外运行 `verify-remote` / `handoff-check`；
- 静态检查不能证明 LLM 运行时一定遵守 Prompt。
