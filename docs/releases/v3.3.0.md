# Workflow V3.3.0 Release Notes

> 本版本聚焦 **TaskBuilder 自主初始化** 与 **任务依赖模型**。Owner 只需提供任务目标或
> 任务清单，TaskBuilder 即可发现基线、生成名称、创建任务分支、初始化任务文件并完成
> 正常交接，不再要求 Owner 充当人工配置器。
>
> 发布状态以 CNB Release 与附件核验结果为准；源码中的 `Published Status` 只是构建
> 产物标记，不等同于平台已发布。

| 项目 | 值 |
| --- | --- |
| Source Version | `3.3.0` |
| Source Commit | 构建时由 `git rev-parse HEAD` 注入（完整 40 位 SHA，不写死） |
| Release Tag | `v3.3.0` |
| 上一版本 | `v3.2.0` |
| state schema | 保持 `schema_version: 3`，无字段变更 |
| Gate | 保持五个 Gate，无新增、无放宽 |

## 1. 升级前必读

V3.3.0 是**任务初始化协议**升级，不改变角色序列、五个 Gate、Evidence Snapshot、
Neutral Tail、Registry 与 DANGER 语义：

1. `state.yaml` 不新增字段，历史任务继续按原 schema 读取；
2. `TB-BRANCH-1` 的旧五要素要求被 `TB-BASE-1` / `TB-NAME-1` 取代；V3.1.0 的旧规则只作历史记录；
3. TaskBuilder 的 Git 权限没有扩大：仍只创建当前任务的初始分支，不做 Merge、Rebase、
   Force Push、删除分支或 Push `main` / 共享集成分支；
4. 工作区存在他人未提交修改时，TaskBuilder 会保留并以 `BOOTSTRAP_HELD` 如实报告，
   而不会为了 clean exit 丢弃或提交这些修改。

## 2. Owner 输入模型

Before（V3.2.0）：

```text
mode: create
owner_request: <需求>
branch:
  name: <Owner 指定>
  base_branch: <Owner 指定>
  base_sha: <Owner 指定的 40 位 SHA>
  authorization: <Owner 的授权原话>
task_slug: <Owner 指定>
```

After（V3.3.0）：

```text
mode: create
owner_request: <任务目标或任务清单>
constraints: <可选>
extra_instruction: <可选>
```

以下覆盖项只在 Owner 主动给出时使用：`task_slug`、`branch.name`、`branch.base_branch`、
`branch.base_sha`、`branch.remote`。缺失不构成停止条件。

Owner 明确要求创建 / 初始化 / 执行任务，即视为授权创建该任务专属的初始 Feature Branch。
该授权不包含 Merge、Rebase、Force Push、删除或重命名分支、Push `main` / `master` /
共享集成分支，也不包含修改其他任务的交付结果。

## 3. 自动基线发现（TB-BASE-1）

核心原则：**当前检出的分支就是默认起始分支，当前 HEAD 就是默认起始 Commit。**

TaskBuilder 会读取：

- 当前分支与完整 40 位 HEAD；
- 工作区已暂存、未暂存、未跟踪文件；
- 当前分支的 upstream；
- 远端是否存在同名分支及其 SHA；
- 本地相对远端的 `AHEAD` / `BEHIND` / `DIVERGED` / `IN_SYNC` 状态；
- detached HEAD、任务目录占用、候选分支合法性与冲突。

明确边界：

- 不擅自切换到 develop / main，不因为当前分支不是预设分支就要求 Owner 提供名称；
- 不用远端最新 SHA 替换当前 HEAD；
- 远端领先 / 落后 / 分叉只记录，不自动 pull / merge / rebase / reset；
- detached HEAD 输出 `BASE_UNRESOLVED`，报告候选分支与 reflog，由 Owner 指定；
- 不使用 `git reset --hard`、`git clean`、`git stash`，不覆盖既有修改。

## 4. 自动命名（TB-NAME-1）

Owner 未指定时，TaskBuilder 从任务目标生成 2～5 个英文小写词的 kebab-case Slug，分支名为
`task/<task-slug>`。名称必须通过 ref 合法性、保留分支、本地分支、远端分支与任务目录检查。

冲突处理：

| 情况 | 处理 |
| --- | --- |
| 同名任务目录且 Goal 相同 | 走 `owner_update` |
| 同名任务目录但 Goal 不同 | 生成带语义后缀的新名称 |
| 本地 / 远端同名分支 | 追加 `-v2` / `-v3` 或更具体限定词，最多 3 次 |
| 仍无法解决 | `OWNER_INPUT_REQUIRED`，给出候选与证据 |

不覆盖已有任务目录或分支，不因为 Owner 没有指定名称而停止。

## 5. TB-BRANCH-1 新流程

```text
读取环境（baseline）
→ 自动确定基线（TB-BASE-1）
→ 自动生成 Slug / 分支（TB-NAME-1）
→ 预检
→ 创建 Feature Branch
→ 写六个初始 Artifact
→ 显式 stage 任务目录
→ pathspec commit（只含任务目录）
→ 普通 Push
→ 远端核验
→ route 自检
→（NORMAL）coder-start
→ handoff-check
→ HANDOFF / BOOTSTRAP_HELD
```

新增结果码：

| 结果码 | 含义 |
| --- | --- |
| `BASE_UNRESOLVED` | detached HEAD 或无法确定安全基线；交 Owner 指定 |
| `BOOTSTRAP_HELD` | Commit / Push 已完成，但保留的他人修改使工作区不干净，无法合法 HANDOFF |
| `TASK_DIR_CONFLICT` | 既有修改落在当前任务目录内，或被预先 stage |
| `READY_WITH_PRESERVED_CHANGES` | `baseline` 的只读状态：可初始化，但报告并保留外来修改 |

`BOOTSTRAP_HELD` 与 `BASE_UNRESOLVED` 不进入 `state.yaml`，不改变 Gate 语义。

## 6. 提问分级（TB-QUERY-1）

| 类型 | 动作 |
| --- | --- |
| 可从代码 / 配置 / Git / 文档确定 | 自行调查，继续 |
| 可合理假设 | 记录 `Assumption`，继续 |
| 暂时不确定但不影响定义 | 记录 `OPEN QUESTION`，继续 |
| 不同答案会改变业务行为 / 一致性 / 安全 | 暂停，向 Owner 提最小问题 |
| 不可逆或越权 | 停止相关操作，取得授权 |

属于 Analyst 职责的技术设计问题不再推回 Owner，而是按 `TB-ROUTE-1` 选择 `COMPLEX` /
`ARCHITECT` 并写入 `## Analyst Questions`。

## 7. 任务依赖模型（TB-DEP-1）

`task.md` 新增可选 `## Dependencies`：

```markdown
## Dependencies
- Blocking：<必须等待的上游正式交付；无则 NONE>
- Reference-only：<仅参考、未交付不阻塞的依赖；无则省略>
- Parallel：<可并行任务；无则省略>
```

- **Blocking**：上游未交付时不初始化、不 HANDOFF，输出 `BLOCKED` + `UPSTREAM_NOT_DELIVERED`；
- **Reference-only**：上游未交付仍可独立调查与定义；不得引用未审查结论，不得伪造其结论；
- **Parallel**：无交付依赖，正常初始化；不等于免审批。

依赖只写入 `task.md`，不新增 `state.yaml` 字段，不引入依赖图引擎。

## 8. 路线判定强化

- 技术栈关键词本身不是路线依据；但任务触及 MQ 可靠性 / 幂等 / 重试 / 补偿、事务 / 库存 /
  并发 / 一致性、权限 / 安全边界、数据模型 / 公开协议、根因不明时，不得判 `NORMAL`；
- 不得为了通过 `coder-start`、减少 Contract 审批或加快开工而降低路线；
- 不得为了保留 `ARCHITECT` 而把业务实现塞进结构 Contract。

## 9. 工具变化（SPEC_ONLY）

`.agent/specs/tools/git-lifecycle-check`：

- 新增 `baseline --task <slug> [--branch <name>] [--json]`：只读报告当前分支、HEAD、upstream、
  同步状态、detached、任务目录占用、候选分支冲突与保留修改；
- `preflight --role TaskBuilder --task <slug> --bootstrap` 不再要求工作区完全干净，但任务目录内
  不得有修改，任务目录不得已存在；
- `commit-check --mode bootstrap --preserve-foreign` 允许保留任务目录外的已暂存内容，并要求
  本次提交范围只含任务目录；
- `bootstrap` 白名单覆盖六个初始 Artifact，修复旧版只允许 `task.md` + `state.yaml` 的不一致。

工具仍为只读；它不能阻止绕过工具的直接 `git commit` / `git push`，也不替代 Gate。

## 10. 兼容性与不变量

- 不新增 Gate、不新增角色、不改变五个 Gate 的语义；
- 不升级 `state.yaml` schema；
- OwnerGate、Cleaner 独立审查、循环熔断与 Engine 只读定位不变；
- 历史任务不需要迁移；
- V3.1.0 的五要素规则已明确标记为历史，不再作为当前要求；
- 任何初始化失败都必须保留现场并如实报告，不得把未执行的验证写成 PASS。

## 12. 已知限制

- TaskBuilder 的决策由 Prompt 约束，Engine 不认证 LLM 是否遵守；机器事实只有 Git、
  `baseline` 输出与 Gate；
- 保留他人修改时，工作区无法 clean，因此不能合法 HANDOFF，只能 `BOOTSTRAP_HELD`；
- GitHub 同步若由外部流水线完成，其状态必须以对端仓库的 Commit / Tag 核验为准；
- 平台侧 `git:release` / `attachments` 行为仍需在真实发布流水线中验证。
